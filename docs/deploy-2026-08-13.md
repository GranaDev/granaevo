### Critério de aceite do Passo 0

```sql
-- (a) as 12 presentes, a nova AUSENTE
SELECT version FROM supabase_migrations.schema_migrations
 WHERE version >= '20260731000000' ORDER BY version;
-- esperado: exatamente as 12 acima. '20260812000000' NÃO pode aparecer.

-- (b) nenhuma alteração de schema causada pela sincronização
--     (rodar ANTES e DEPOIS; os números têm de ser idênticos)
SELECT
  (SELECT count(*) FROM pg_class c JOIN pg_namespace n ON n.oid=c.relnamespace
    WHERE n.nspname='public' AND c.relkind IN ('r','v'))            AS objetos,
  (SELECT count(*) FROM pg_policy)                                   AS policies,
  (SELECT count(*) FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace
    WHERE n.nspname='public')                                        AS funcoes;
```

## Passo 2 — Edge Function `login-lockout`

```
supabase functions deploy login-lockout
```

Já tem entrada em `supabase/config.toml` com `verify_jwt = false` — obrigatório,
porque ela é chamada quando **não existe** usuário autenticado (a senha acabou
de falhar).

**Aceite:** chamada sem `x-proxy-secret` → **403**; com secret e `id` fora de
`^[0-9a-f]{32}$` → **400**.
